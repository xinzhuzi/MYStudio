# 《三国望神州》AI Visual Bible v2.2
## 美术风格分析、视觉 DNA、LoRA 筛选与 ComfyUI 生产规范

> **版本：v2.2**  
> **定位：** 在 v2.1《三国望神州》美术风格分析与 AI 生图 / LoRA 筛选规范基础上的生产化升级版。  
> **用途：** Civitai / Hugging Face / Tensor.Art 模型筛选、LoRA A/B 测试、ComfyUI 工作流设计、角色与场景批量生产、AI 漫剧连续镜头开发。  
> **核心原则：** 不寻找一个“万能国风 LoRA”，而是建立一套可拆分、可测试、可复现、可长期维护的视觉系统。

---

# 0. Executive Definition / 核心定义

## 0.1 一句话定义

> **《三国望神州》目标视觉 = 中国传统人物画审美 DNA + 工笔/白描线条 + 水墨空气与虚实 + 传统色体系 + 连环画叙事 + 古典空间构图 + 现代游戏角色设计与数字绘画完成度。**

这里的目标不是复刻某一幅古画，而是：

> **把中国传统绘画的视觉规则重新组织为现代历史题材游戏美术。**

---

# 0.2 “新中式”在本项目中的位置

“新中式历史叙事游戏美术”可以作为本项目的**内部工作分类**，但不将其视为《三国望神州》的官方风格标签。

更准确的关系是：

```text
《三国望神州》目标视觉系统
│
├── Traditional Art DNA
│   ├── 中国人物画
│   ├── 工笔
│   ├── 白描
│   ├── 水墨
│   ├── 连环画
│   └── 古典山水
│
├── Modern Game Translation
│   ├── 现代角色设计
│   ├── 商业插画完成度
│   ├── 数字绘画
│   ├── 清晰视觉焦点
│   └── 可控材质与光影
│
├── Graphic / Presentation Language
│   ├── 画卷
│   ├── 画册
│   ├── 连环画分镜
│   ├── 书法 / 字体
│   └── 装饰性视觉元素
│
└── Historical Content
    ├── 时代
    ├── 身份
    ├── 服饰
    ├── 甲胄
    ├── 兵器
    └── 建筑 / 场景
```

因此本项目内部可以使用“新中式历史游戏美术”来方便检索，但模型筛选时不要让“新中式”本身成为唯一搜索标准。

# 1. Core Visual DNA / 核心视觉 DNA

建议以后所有风格判断，都回到以下 8 个维度。

| DNA 层 | 核心问题 | 主要控制手段 |
|---|---|---|
| 01 Character Rendering | 人物像不像现代历史游戏角色 | Style LoRA / Reference |
| 02 Line Language | 线条是不是中国人物画逻辑 | Line LoRA / Prompt |
| 03 Ink Language | 水墨是空气、虚实还是黑白滤镜 | Style / Background |
| 04 Color Language | 是否使用传统色并保持受控 | Prompt / LoRA / Color pass |
| 05 Spatial Language | 空间是否有呼吸与古典层次 | Reference / ControlNet |
| 06 Graphic Language | 是否具有画卷、连环画、分镜感 | Reference / Layout |
| 07 Historical Language | 服饰、身份、甲胄是否统一 | Costume / Armor LoRA |
| 08 Material Language | 布、木、石、金属是否统一于绘画表现 | Style / Detail Control |

---

# 2. Character Rendering / 人物表现

## 2.1 基本目标

人物应同时满足：

- 成年人物结构
- 清晰骨骼和比例
- 明确身份与年龄感
- 游戏角色的完整资产感
- 中国人物画式线条
- 历史服饰与配件逻辑
- 克制表情
- 不依赖典型二次元美型模板

目标不是：

```text
古画人物
```

也不是：

```text
欧美游戏角色
```

而是：

```text
现代历史游戏角色
        ×
中国人物画线描逻辑
        ×
历史身份设计
```

---

## 2.2 Face / 面部

### 优先

```text
mature facial structure
historical character identity
subtle expression
distinctive facial features
natural age cues
restrained attractiveness
```

### 避免

```text
generic anime beauty
idol face
K-beauty face
childlike face
uniform handsome face
plastic skin
photographic beauty retouching
```

原则：

> **人物应该“有身份”，而不是“统一地漂亮”。**

---

# 3. Line Language / 线条语言

## 3.1 这是核心 DNA 之一

目标：

- 细
- 稳
- 有轻重
- 有起伏
- 轮廓清晰
- 五官结构明确
- 衣褶与甲胄结构可读
- 发冠、佩饰、武器具有设计感

理想描述：

> **线条像画出来，而不是像 AI 自动勾边。**

---

## 3.2 Prompt Vocabulary

```text
fine Chinese linework
fine ink contour
delicate brush line
controlled contour weight
expressive ink line
traditional figure outline
fine facial linework
structured garment linework
```

### Negative Vocabulary

```text
thick anime outline
bold cel-shading outline
western comic inking
uniform black outline
sticker-like contour
vector-like outline
```

---

# 4. Ink Language / 水墨语言

## 4.1 正确理解

水墨不是黑白滤镜。

它主要承担：

```text
墨色浓淡
虚实边缘
空气透视
远景淡化
局部晕染
背景层次
笔触节奏
```

因此目标更接近：

```text
subtle ink atmosphere
controlled brush texture
soft ink transitions
faded distant background
soft edges
light ink wash
```

而不是：

```text
heavy ink splash
black-and-white filter
extreme splash ink
chaotic brush texture
```

---

# 5. Color Language / 色彩系统

## 5.1 核心不是“低饱和”

更准确的定义：

> **传统中国色体系 + 受控饱和度 + 受控对比度 + 角色识别色。**

颜色可以存在，也可以较鲜明；关键是不要让画面失去视觉层级。

---

## 5.2 建议色彩结构

```text
Base Palette
│
├── 宣纸白 / 米白
├── 墨黑 / 墨灰
├── 土黄 / 赭色
├── 青灰 / 石青
├── 青绿
└── 棕灰
        ↓
Character Accent
│
├── 朱红 / 绛红
├── 暖黄 / 赭黄
├── 青色
└── 少量金属暖色
```

### 正确关系

```text
大面积稳定基底
+
中等强度人物色
+
少量高识别强调色
```

### 错误关系

```text
全屏青色滤镜
全屏灰褐滤镜
金蓝高对比
荧光红蓝
赛博紫
```

---

# 6. Spatial Language / 空间与留白

## 6.1 留白的正确定位

> **留白不是“画面必须很空”，而是“控制视觉密度和信息优先级”。**

留白主要承担：

- 主体突出
- 空间呼吸
- 情绪表达
- 前中后景关系
- 远近虚实
- 视觉引导

因此以后不用“必须大留白”作为单一规则，而使用：

```text
Visual Density Control
```

---

## 6.2 不同场景的留白等级

| 场景 | 留白 | 视觉密度 | 动态 |
|---|---|---|---|
| 角色立绘 | 中 | 中高 | 低 |
| 剧情场景 | 高 | 低中 | 低 |
| 山水远景 | 很高 | 低 | 低 |
| 战斗画面 | 低中 | 中高 | 高 |
| Key Art | 中 | 中高 | 高 |
| 连环画叙事 | 按镜头变化 | 中 | 中高 |

---

# 7. Classical Composition / 古典构图

场景目标：

```text
classical Chinese composition
open composition
atmospheric perspective
layered mountains
quiet architecture
sparse vegetation
clear foreground / midground / background
visual breathing space
```

不要把它理解成“直接贴一张古画背景”。

更准确：

> **古典山水构图规则 × 现代游戏空间。**

---

# 8. Graphic / Presentation Language / 图形与包装语言

这是 v2.2 新增的独立层。

## 8.1 为什么必须单独拆出来

“像《三国望神州》”不仅是：

```text
怎么画
```

还包括：

```text
怎么组织画面
怎么呈现故事
怎么包装角色
怎么进入画卷 / 分镜 / UI
```

因此新增：

```text
Graphic Presentation
│
├── Handscroll / 画卷
├── Album / 画册
├── Comic Panel / 连环画分镜
├── Typography / 书法与字体
├── Decorative Motifs / 装饰纹样
└── UI Framing / 古典视觉框架
```

---

## 8.2 AI 漫剧的意义

AI 漫剧不要只锁：

```text
Character
Costume
Style
```

还要锁：

```text
Shot Language
Panel Layout
Narrative Framing
Visual Hierarchy
```

这样连续 100 张图才有机会被识别为：

> **同一部作品。**

# 9. Historical System / 历史系统

## 9.1 画风与服饰解耦

这个原则继续保留：

> **画风解决“怎么画”。  
> 服饰解决“穿什么”。**

但 v2.2 增加一个重要约束：

# Era Lock / 时代锁

---

## 9.2 历史约束结构

```text
Historical Character
│
├── Era
├── Region
├── Social Status
├── Civil / Military
├── Costume
├── Armor
├── Headwear
├── Accessories
└── Weapon
```

不要只写：

```text
Chinese ancient clothing
```

而要尽量明确：

```text
Era
+
Identity
+
Status
+
Costume Set
```

---

## 9.3 防止跨时代污染

典型错误：

```text
宋代服饰
+
汉代甲胄
+
明代发冠
+
唐代配饰
```

这类结果不能仅因为“都是中国元素”就判定为合格。

# 14. LoRA Evaluation / 模型评分体系

保留 10 分制，但新增“角色 / 场景适用范围”。

| 指标 | 权重 | 判断 |
|---|---:|---|
| 中国人物画 DNA | 20% | 传统人物画骨架是否明显 |
| 现代游戏完成度 | 20% | 是否能够成为现代游戏资产 |
| 线条质量 | 15% | 细、稳、有变化 |
| 空间 / 视觉密度控制 | 10% | 能否控制留白与背景密度 |
| 色彩系统 | 10% | 传统色 + 受控饱和 |
| 历史适配 | 10% | 与时代 / 身份系统兼容 |
| AI 模板感 | 10% | 是否有明显“AI 国风”模板感 |
| 模块兼容性 | 5% | 与其他 LoRA / Reference 能否共存 |

# 15. Production Gate / 生产准入

替代“一票否决”。

一个模型可以处于：

```text
S 级：主生产候选
A 级：辅助生产候选
B 级：特定场景 / 特定角色
R 级：Reference / DNA 研究
X 级：淘汰
```

例如：

```text
传统人物画 DNA 极高
现代游戏完成度低
```

不一定 X。

它可能是：

```text
R 级 DNA Reference
```

# 20. Scene / Character / Battle 三种视觉密度

## 20.1 Story / 剧情

```text
Density: Low ~ Medium
Motion: Low
Negative Space: High
Line: High
Atmosphere: High
```

## 20.2 Character

```text
Density: Medium
Character Detail: High
Background Detail: Low

```

## 20.3 Battle

```text
Density: Medium ~ High
Motion: High
Ink Impact: Medium ~ High

```

> **动作强度增加，不等于视觉语法切换成仙侠 CG。**

# 21. Material Language / 材质语言

v2.2 新增。

历史题材游戏虽然采用传统绘画 DNA，但并不意味着所有物体都必须失去材质差异。

应区分：

```text
布料
木材
石材
金属
皮革
纸张
水体
```

但表现方式应仍然服从统一的绘画语言。

### 目标

```text
Material difference: clear
Rendering language: unified
```

而不是：

```text
每种材质都变成独立的 3D 写实渲染
```

# 30. Identity Consistency / 角色一致性

AI 漫剧最重要的稳定性之一不是“每张都漂亮”，而是：

> **同一个人连续出现 20 张时仍然像同一个人。**

因此建议控制：

```text
Face Reference
Character LoRA
Costume Lock
Color Accent
Silhouette
Hair / Headwear
Weapon
```

生成顺序尽量：

```text
身份
→
服饰
→
姿态
→
场景
→
镜头
```

而不是每一张独立 Prompt。

# 32. Acceptance Criteria / 最终验收标准

一张图不能只问：

> “好不好看？”

应该同时回答：

### A. Style

是否符合目标视觉 DNA？

### B. Character

人物是否具有明确身份？

### C. Historical

时代、服饰、甲胄、配件是否自洽？

### D. Line

线条是否具有中国人物画式特征？

### E. Color

传统色是否被正确组织？

### F. Space

视觉密度是否受控？

### G. Presentation

是否具有统一的画卷 / 连环画 / 游戏图形语言？

### H. Consistency

放进整个项目后，是否仍然像同一部作品？

# 33. Final Visual Target / 最终视觉目标

最终希望达到：

> **第一眼：这是现代游戏。**
>
> **第二眼：这是有深厚中国传统绘画底蕴的现代游戏。**
>
> **第三眼：人物像现代游戏角色，但线条、色彩、空间、服饰和叙事方式明显来自中国人物画、工笔、白描与连环画。**

最终目标不是：


也不是：

```text
最国风
```

# **× Chinese Figure Painting DNA**
# **× Lianhuanhua Narrative**
# **× Historical System**
# **× Traditional Color**
# **× Controlled Spatial Density**
# **× Graphic Presentation**

# 35. v2.2 Revision Notes / 版本变更

## v2.2

本次升级重点：

1. 将“新中式”从官方风格判断调整为**内部工作框架**。
2. 将“留白”升级为更准确的 **Visual Density Control**。
3. 将“低饱和”修正为 **Traditional Palette + Controlled Saturation + Controlled Contrast**。
4. 新增 **Graphic / Presentation Language**。
5. 新增 **Material Language**。
6. 历史服饰系统新增 **Era Lock**。
7. 明确 Composition 不应主要依赖 LoRA，而应更多使用 Reference / ControlNet。
8. LoRA 权重改为“实验区间”，不再作为固定规范。
9. “一票否决”改为 **Production Gate**。
10. Prompt 从抽象风格标签进一步转向可观察视觉特征。
11. Negative Prompt 改为模块化。
12. 增强 AI 漫剧中的角色身份一致性与视觉锚点设计。
13. 新增 Master Reference / Visual Anchor Set。
14. 新增统一的模型元数据记录规范。
15. 将最终目标从“单张图片漂亮”提升为**大规模资产的一致性**。
