## 三、六层排查链(每层都是验证侧的坑,教训在案)

1. 设备层:手拉引擎丢 manifest `launchArgs`(vramPolicy=gpu-only 等)→ TE 落 CPU → float16 生成崩(早期 EOS)。**手拉引擎必须带全参数**。
2. 取件层:`easy showAnything` 真口名=`anything`(object_info 的 **optional** 键),传错被引擎静默忽略 → history text 恒空。
3. 历史层:九型英文终稿=当时引擎家 py 未随根修同步(.py 改须**重启引擎**才加载)。
4. 接线层:诊断链手搓直连自研节点 ≠ 产线接线;**节点级验证必须含产线接线核**(注册≠上线)。
5. 输入形态层:F1-v2 换件后仍英文 → 短输入中文/长输入英文的表象,误导一轮。
6. **检查点层(真凶)**:history 取证产线两发英文跑的 [6:4019] 均=pe_t2i → 实验矩阵定谳。

## 五、方法论沉淀

- 引擎状态三件套零缓存(真 PID CPU 增量+活跃日志 mtime+队列 API;`ls -t|head -1` 惯性路径会拿旧 stdout 骗人)
- 投递即定位(第 N 位/前面是什么/预计多久),禁「在跑」式回答
- 先查存量再烧算力;自研节点三层测试序(纯函数→纯文本推理→完整图)
- API 直排的 `resolution` 参数是**像素基准**(0-4096,模板用 1024),不是兆像素
- heredoc python 禁配 `&`+run_in_background 双层后台(SIGHUP 连带收死);轮询脚本空取件必须退出
