# 插件更新链故障台账(2026-09-19 全天实弹,13 bug 根修录)
最后核账:2026-09-22

> 真源:设置 → 本地配置 → ComfyUI → 更新页(插件装/更/卸链)。
> 当天用户连续报障,剥洋葱式挖出 13 个叠加 bug;本文=根因、防线、收口纪律,
> **下次动这条链前必读,同类问题按此台账对照,不许再犯**。

## 一、故障的五层叠加模型(为什么"修一个冒一个")

```
用户点「更新」
  → ①网络层:直连 GitHub 超时(整段死,非慢)          → 修复:代理探测接管
  → ②git 策略层:tag 覆写拒绝(! [rejected])           → 修复:pull --force(仅 fetch 侧)
  → ③本地状态层:半装残留(目录在/台账无)= 按钮全无死端  → 修复:收编登记+修复钮
  → ④依赖层:requirements 的 git+URL 行炸预检解析       → 修复:VCS 行跳过区间预检
  → ⑤判定层:更新成功后最新版缓存(24h TTL)不作废      → 修复:成功即写 latestSha
  → ⑥UI 层:进度条两处/互斥不可视/清单不刷新/轮询不熔断  → 修复:见下表
```

每一层修通后,下一层的症状才第一次具备显形条件——**排障必须逐层验证到底,
不能按「我修过的清单」收口,要按「用户可见状态穷举」收口(见第四节)**。

## 三、既定行为(不是 bug,排障时勿误判)

- **收编的裸拷贝 6 件无 .git**(Frame-Interpolation/kjnodes/spectrum/videohelpersuite/krea2-vl/krea2edit-assembler):更新钮点击报「没有 git 历史,请卸载重装」——09-11 裁定的正确拒收;
- **ComfyUI-Manager.已退役-git线-0911 目录**:体检报「多余没登记」属预期(手动存档),点「清理多余」会删;
- **pip 线 Manager 合成行**:无可更新判定(版本走 pip 链),更新钮随 source 透传出现;
- **本机补丁三件**(超分 mps/krea2edit MPS 插值/未来新增):装机不含,重装引擎后要重打——补丁登记表机制待立项(见第五节)。

## 四、收口纪律(违者重蹈覆辙)

1. **按用户可见状态穷举收口**:每行 × {未装/可装/已装/可更新/半装残留/装失败} × 每钮 {安装/更新/卸载/修复登记},穷举一遍无死态才算完——**不是按「修过的 bug 清单」收口**;
2. 三方真值对拍:台账 commit / GitHub 缓存 latestSha / `git ls-remote` 远端 HEAD,三值一致才算状态正确;
3. 排障网络类首查代理:`curl -x http://127.0.0.1:7897 https://github.com`(探测优先制,禁「先直连失败再回退」——直连对 GitHub 是整段超时死);
4. 报错原文以引擎日志/sidecar 日志为准,**视觉读图文字不可直接当 grep 关键词**(当日三次读错的教训);
5. 外站 git/pip 改动一律走 `common/net_outbound` 三件口;回环(127.0.0.1)与国内后缀恒直连。
