## 一、门规则：逐字在场比对，缺席禁派发

规则本体两条：

1. **逐字在场比对**：派发前，把「计划文案清单」（台词 + 屏幕可见文字）逐条与最终 prompt 做比对——每条计划文案必须作为**连续子串一字不差**地出现在最终 prompt 里（含标点）。
2. **缺席禁派发**：任一条缺席（被压缩/意译/改写/吞词/漏句），该镜**禁止派发**，退回上一环节修正；不做「差不多在场」的宽松匹配。

为什么需要：**防漏词、防改写**。文案从分镜表到提示词要经过誊写/改写/拼接等环节，任何一环都可能无声丢字——少一个字，成片上就是口型与台词对不上的事故，且批量生产里最隐性。「对白逐字」本身已是 H3 提示词的写时硬规则（`base-en.txt` §4.4；中文直投路径 `.agents/skills/h3-prompt-writing/references/direct-zh.md` §一③），本门把「写时保真」延伸为「**发前验真**」。

比对口径：

- 查询集=计划文案清单（分镜表台词列的**角色行**、屏幕文字清单），**不以最终 prompt 反推**——反推验不出「该写而没写」的漏句。台词列里只有角色行（有冒号且说话人非旁白标签）是 H3 的计划文案；旁白行（宽集标签「旁白/vo/画外音/解说」+无冒号整行，2026-10-11 统一判定源口径）归外挂 TTS 线，**不入清单**——它本就不进 prompt，缺席不是事故；
- 逐字=字符级连续子串匹配（中文按字、英文按词与标点），禁同义替换、禁近似匹配；
- 屏幕可见文字（招牌/字幕条/霓虹字等）与台词**同权**入清单（屏幕文字同样逐字：`base-en.txt` §4.5）。

## 二、漫影落点：组装器派发前校验（已代码化，2026-10-01）

落点：漫影 H3 单镜派发链的最后一跳——组装器 `apps/frontend/lib/assist/image-studio/h3-shot-prompt.ts`（官方英文字段结构的产线真源，`direct-zh.md` 定位表同名引用）产出最终 prompt 之后、入队派发之前，加一道逐字在场校验；校验对象=`buildShotH3Prompt` / `buildShotH3RefPrompt` 返回的 prompt 串。

现状盘点（2026-09-30 核）：

- 组装器 `renderDialogue` 把台词正文原样注入 `<d>[Chinese] …</d>`——单镜直注路径**天然逐字**，当前代码路径上没有改写环节。10-11 音频分工后口径收窄：只渲染**角色行**（旁白行不再进 prompt、改走外挂 TTS；旧「画外音短语+唇闭声明」的旁白渲染随之退役），says 短语可挂 voiceMood 音色锚（`says in a 〈情绪〉 tone:`，锚在 `<d>` 外，不碰逐字正文），无角色行的镜渲染 "lips stay closed" 唇闭声明（ambient 音效床）；
- 因此本门在当下的主要守面是：①未来引入 LLM 改写/润色环节时（H3 技能 references 本身就是「改写」方法论，改写链是合理演进方向）；②人工直投稿（`direct-zh.md` 形态，§一③ 逐字原文是硬规则但无机器验）；③文案清单与组装输入的传导断点（清单改了、入参没跟上）。

形态声明：本文 §一 已于 2026-10-01 代码化（任务 10-01-a7），不再是设计注记。落点=纯函数 `verifyPlannedTextVerbatim`（`apps/frontend/lib/assist/image-studio/h3-shot-prompt.ts`，逐条连续子串一字不差、空/空白清单放行）+ 派发点接线 `assertPlannedTextVerbatimGate`（`apps/frontend/lib/assist/image-studio/h3-shot-video-workflow.ts`，`buildShotH3Workflow`/`buildShotH3RefWorkflow` 产 prompt 后、注入工作流前，缺席即抛大白话中文错误阻断派发，冒泡至桥消费 onError→toast）。清单口径（2026-10-11 音频分工更新）：仅 full 档的**角色行**入清单（`extractPlannedDialogueTexts` 只取 `splitDialogueLines(lines).character` 正文，与 `renderDialogue` 同一解析源）；旁白行（宽集标签+无冒号整行，统一判定源）归外挂 TTS，不入 prompt 不入清单；ambient/bare 档台词走 TTS 线不进 prompt，清单为空不拦。full/ambient 由纯函数 `dialogueAudioPolicy(lines)` 逐镜派生（有角色行→full；派发点 ComfyCanvasStudio 单镜组装注入，不再硬编码 ambient）。屏幕可见文字字段入数据模型后同权追加进清单。测试=`h3-shot-prompt.test.ts`（命中/缺席/空清单/标点差异四型；10-11 增统一判定源拆行/dialogueAudioPolicy/externalNarratorSpokenText 表驱动、full 只注角色行、音色锚在场与缺省、ambient 唇闭回归锁）+`h3-shot-video-workflow.test.ts`（接线放行/阻断/voiceMood 透传）。

## 三、域边界：与容量门、分镜质控门的分工（互链不代述）

本门只管「文案是否逐字在场」。相邻各门各管各的，互链不代述：

| 门 | 管什么 | 真源 |
|---|---|---|
| 容量门（手工） | 台词装不装得进时长：从时长算字数上限，写提示词前手工复核 | `.agents/skills/h3-prompt-writing/references/direct-zh.md` §三 |
| 容量门（产线 lint） | 分镜表入队前的容量机检（提案形态，未落地） | `docs/research/PIPELINE_METHODS_ABSORPTION_ANALYSIS_2026-09-28.md` 提案二 |
| 分镜质控机检硬门 | 分镜表本身的六项硬门（hook 密度/单镜时长/角色数/空间锚点继承/每秒覆盖/连续性链） | [参考_拼接衔接锁与一致性锚点.md](./参考_拼接衔接锁与一致性锚点.md) §二 |
| **本门（逐字在场）** | **计划文案是否一字不差进了最终 prompt（派发前最后一跳）** | 本文 |

一句话分界：容量门问「**说得完吗**」，质控门问「**分镜表合格吗**」，本门问「**一字不少地进去了吗**」——三问互不替代（跨域边界写法先例：`direct-zh.md` §二、§三末）。
