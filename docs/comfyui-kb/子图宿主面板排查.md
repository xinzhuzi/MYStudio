# 子图宿主面板排查(输入点不渲染/错名/widget 丢失)

> 2026-10-05 定谳。当日 [6] 文本提示词类型优化子图「说了一下午还不改」的完整根因链落档。
> 适用症状:子图宿主节点(主图里那个实例)**输入点全无 / 显示输出口名字当输入 / widget 控件消失 / 连线消失或接错**。

## 一、宿主槽渲染终极机制(2026-10-05 晚活机+前端源码定谳,先读这节)

宿主节点输入槽渲染成「带名字连线点」还是「widget/裸点」,**与宿主节点 JSON 序列化无关**(前端 `SubgraphNode.configure` 会从子图定义重建宿主 inputs,序列化只是回写产物)。决定链:

1. 前端 `_resolveInputWidget` 沿子图边界线找**内部落点**;
2. 落点是内部节点的**带 widget 输入**(multiline STRING / COMBO / BOOLEAN 等)→ 该 widget 被**提升(promote)**到宿主——连线后渲染为**裸点无标签**且占位;
3. 落点是 **forceInput 纯槽**(`("STRING", {"forceInput": True})`)→ 宿主渲染**带名字的连线点**;
4. MODEL/CONDITIONING/LATENT/IMAGE/VAE 天然无 widget → 永远带标签点(加速子图参照)。

**修法**:要「带名字连线点」→ 把边界线落点的内部节点输入声明为 `forceInput`(实例:`MyQi21PESwitch.主体句`、`MyQi21SubjectSelect.主体句负面`);要「宿主控件」→ 保持 widget 型输入被提升(型选择/PE启用? 正是此形态)。改节点 `.py` 须重启引擎(队列==0 硬门);改工作流 JSON 走四路热修(下节)。

**控件 vs 展示框分界(1006 立,动手前先读)**:面板物分两类——**控件**(COMBO/BOOLEAN/INT 等参与计算的输入件)=退役/删除类指令的合法对象;**展示框**=optional multiline 只读文本框(值两源:出生=JSON `widgets_values` 预填快照,运行期=JS `onExecuted` 回填覆盖;只展示不参与计算),**不是控件**——任何「退役/清空/转零控件/删下拉框」类指令的默认范围不含展示框,删它必须用户点名;删控件后同批重对 `widgets_values`(位置制,少一项全表错位;宿主镜像与 `sg.widgets` 同步)。全文=node-graph 技能「自研节点设计纪律」§5。
