# 工作流落位规范(09-21 立规矩,单源)

> 回答一个问题:**「工作流 JSON 在这台机器上只允许放在哪、放错了怎么发现?」**
> 背景:09-21 用户问责「很多 json 工作流的位置没规划好」——会话活动曾把工作流副本写进引擎家用户区(分叉旧版)、把排版中间件入库、把参考件目录起了三种名字、把临时产物散在 /tmp 与仓库根。本文件是落位唯一口径;审计工具 `apps/build/scripts/workflow_placement_audit.py` 按本文件机检。

## 一、应然落位表(全机唯一)

| # | 落位 | 角色 | 规则 |
|---|---|---|---|
| 1 | 仓库 `apps/backend/engines/comfyui/workflows/` | **唯一真源** | 域分类(0_分镜/1_图片/2_视频/3_声音);命名铁律=无 `MY-` 前缀、无下划线;逐件账本=`漫影工作流清单.md`(计数锚点 `<!-- audit:workflow-tree-total=N -->`);新增/删除须经所有者裁定并同步清单 |
| 2 | 引擎家用户区 `<comfy-home>/ComfyUI/user/default/workflows/` | 用户手动另存区 | **会话恒零写入**;只允许用户在画布里另存副本;`.cache` 等杂物同禁 |
| 3 | 引擎家 `snapshots/` | 引擎快照 | `workflow-backups/` 不得出现分镜逐章/逐镜实体(分镜域零实体,09-15 裁定) |
| 4 | `docs/comfyui-kb/参考_*/` | 外来参考工作流 | 目录名一律 `参考_` 前缀(现例:`参考_换装工作流/`、`参考_提示词工程/`);参考资料永不入生产库 |
| 5 | `docs/comfyui-kb/备份_*/` | 历史版本备份 | 目录名一律 `备份_` 前缀(现例:`备份_工作流/`) |
| 6 | `~/Downloads/<专项目录>/` | 会话临时产物 | 临时出图/中间 json/探针一律进专项目录;禁 `/tmp` 当家、禁仓库根、禁引擎家 |
| 7 | release 包内副本 | 构建产物 | 随 `build-mac.sh` 从真源同步生成,永不手工碰;真源净则它净 |

**新工作流只有三个合法去处**:① 真源(经所有者裁定+入清单账);② 参考区(`参考_*`);③ 临时区(`~/Downloads/专项目录`)。再无第四处。

## 二、禁项(违者审计翻红)

1. 会话/AI 向引擎家用户区写任何工作流文件(写操作是用户画布「另存」的专属权限,修改铁律见清单 09-14 条)。
2. 生产库内出现 `MY-` 前缀件、下划线命名件、`.laid-out.json` 等排版中间件、`-测试`/`-旧版` 等留档件(留档件须在清单有账,无账即野件)。
3. `.api.json` 桥格式件必须与同名 UI 件成对存在(现行 3 对,Yue2);孤立 `.api.json` 即脏件。
4. 仓库根、`/tmp` 散落工作流 json / 截图 / 探针。
5. 引擎家出现分镜逐章/逐镜实体(`snapshots/workflow-backups/` 恒空或不存在)。

## 三、审计(装机核验两硬检查的落地)

```bash
python3 apps/build/scripts/workflow_placement_audit.py
```

检查项:真源计数=清单锚点;用户区零 json;用户区零 `MY-` 残留;snapshots 无分镜实体;真源无 `.laid-out.json`/`MY-` 件;`.api.json` 全成对;docs 参考区无旧命名目录;仓库根零 PNG。任一 FAIL 退出码 1。
