# Runbook:画稿上色工作流·错误应对手册

> Trellis 计划产物 | 2026-09-07 | 配合 implement 清单使用;每条故障给:症状→根因→处置→升级路径
> 引用的机制均为本机实证(来源:快流/稳定流排查档案),标注[实证]的已在本机复现过

## A. 首跑症状故障树(按出现概率排序)

### A1. 线稿结构崩(轮廓糊/五官变形/线条消失)——最大风险
- 根因:krea2edit 训练于成品图编辑,纯线稿=分布外;denoise1.0 全重绘下参考锚定不够强
- 处置阶梯(一次只动一个旋钮,每档跑一张):
  1. ref_boost 4→6(参考注入加强,身份/结构锚定增益;注意过高会画面僵硬)
  2. 上色指令里保线句加权:「严格保留画稿的每一条轮廓线条」放句首
  3. 降分辨率试试(1MP→0.75MP,降低结构复杂度)
  4. 若仍崩→**走 Plan C 线稿叠底**(见 design「备选路线」,数学保线,最强兜底)
- 判定:轮廓/五官/服装形态肉眼可辨=可接受;崩=进入阶梯

### A2. 色彩没进去(图出来还是黑白/灰)
- 根因①:上色指令触发审查被吞(即使指令文字不裸露,画稿内容裸露也可能触发)[机制同稳定流「文字描述没有生效」实证]
- 处置:确认 Mystic@2.0 在位(检查是否被误旁路/降强度;低于 1.0 已实证不够)
- 根因②:指令缺「动作锚」——只有色彩描述没有「为这张画稿完整上色」的动作指令
- 处置:核对指令骨架完整(动作锚→色彩段→保线句→身份锁四段缺一不可)

### A3. 完全没编辑(输出≈线稿原样)
- 根因:identity 编辑闸被压(强度<1)或 Mystic 不在位——与稳定流「identity0.2+没修改」同构[实证]
- 处置:核对三 LoRA 配比 = identity@1.0 / Mystic@2.0 / pussy@0.15;denoise=1.0

### A4. 放飞(自由生成,和线稿无关)
- 根因:编辑链断开(参考没进模型)——[8]VAEEncode→[14].source_latent 或 [17].image 连线断
- 处置:静态自检连线;对照 design 架构图逐线核对

### A5. 报错 "Adaptive pool MPS" / adaptive_avg_pool2d
- 根因:krea2edit 的 _prep 用 area 缩放,MPS 非整除尺寸必炸[实证]
- 处置:两个接地编码的 grounding_px 必须=0(原生分辨率跳过缩放);若已 0 仍报→检查线稿尺寸是否极端比例,裁到常规比例(如 2:3)

### A6. 模式B(参考取色)无效——出图配色与参考图无关
- 根因:image_b 链没接对(插件双图口语义与预期不符,定位是 person+scene 编辑非取色)
- 处置阶梯:①object_info 核对 image_b 类型与接法 ②指令强化「参考第二张图的配色」 ③仍无效→模式B降级为「留口不接」,需求用模式A(文字)覆盖;真需要取色再立项

### A7. API 提交 400(node_errors 非空)
- 根因:常见=数组 widget 走 API 格式必 400[实证]/字段名拼错/图片文件名不存在
- 处置:API 格式必须用 inputs dict+精确输入名(object_info 核对);LoadImage 的文件名先 ls input/ 确认

### A8. 前端打开工作流报「检测到错误」/红色节点
- 根因:新增节点 required 输入悬空[实证:历史两起同类事故]
- 处置:零连线节点扫描+required 输入全覆盖检查(implement 清单第4步的两道校验)

## B. 环境类故障

### B1. 端口不通/服务器没响应
- 处置:`lsof -nP -iTCP:17598 -sTCP:LISTEN` 确认;Desktop 重启=用户门禁(安静等自愈 30s~10min,别抢 spawn)[实证]

### B2. 内存压力(交换频繁/系统卡)
- 处置:本机 128GB+reserve-vram16 常态够用;若 LM Studio 同开(27B 占 16GB+),先关再跑

### B3. 改了工作流但 UI 没变化
- 处置:侧边栏刷新→重新打开;旧标签页别保存(会反向覆盖磁盘)[三实案实证]

### B4. 测试跑完历史里留了任务
- 处置:POST /history body {"delete":["<prompt_id>"]}(DELETE 恒 405)[实证];本工作流的冒烟测试读完结果即自清

## C. 升级路径

- A1 阶梯走完仍崩 → 报告+Plan C(叠底)方案启动,或暂停等 lineart 权重
- A6 降级后仍强需求取色 → 单独立项(参考取色专用调研)
- 任何 execution_error 拿不准 → 抓 history 里 node_id/exception_message/traceback 三件套再分析
