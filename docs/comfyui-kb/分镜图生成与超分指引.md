# 分镜图生成与超分指引(分镜×H3 配套,实施前先读)

> 2026-09-14 定稿。回答三个实施必答题:分镜图怎么生成、一镜几张图最佳、要不要本地超分。
> 标注口径同参数速查:【实测】= 本机跑过;【文档】= 技能/官方文档;【裁定】= 用户拍板;【调研】= 09-14 生态调查结论(见 [research/H3_COMIC_DRAMA_ECOSYSTEM_RESEARCH_2026-09-14.md](../research/archive/H3_COMIC_DRAMA_ECOSYSTEM_RESEARCH_2026-09-14.md))。
> 参数类事实(帧网格/分辨率/排名)不重复抄,查 [参数速查](./参数速查.md) H3 段。

## 一、分镜图生成链路(现状 + 实施要点)

**现状链(已建成)**:资产环节出角色定妆照(三视图+造型变体)、场景四视图、道具图 → 分镜环节每镜一张卡（当前 `MyShot` 锚点；旧 `ManyingShot` 为兼容别名）→ K2 本地生图走 ComfyUI 桥,参考图自动装配(约 1 主体 + 3 参考)→ 单镜图落卡。

**生成写法要点**【调研+漫影实践一致】:

1. 六要素顺序:景别 → 画面事物 → 时间光照 → 色调 → 构图 → 质量词;**禁比喻修辞**(写「鲤鱼跃出水面高度较高」,不写「像长了翅膀」)。
2. 风格词统一挂载:用 AI 提取的纯风格短语(视觉手册已有),不要每镜手写风格。
3. **有台词的镜头用近景正面**——给 H3 对口型留余地。
4. 美术风格词与事物/氛围描述分离(从参考图剥离提炼)。

**实施要补的一步**:分镜图「关联资产」目前只喂 K2 生图,尚未接到 H3 的 Ref2VA 参考槽(吸收分析 P0-2 素材调度)。补上后首帧+定妆照+场景图一起喂 H3,一致性再上一档。

## 二、一镜张数策略:分用途,不是越多越好

**先记住硬事实**:H3 的 Picture 槽只有 2 个语义位(首帧/尾帧)【实测:`Picture 槽位=首/尾帧图,不是自由参考槽;场景图禁占 Picture2`】;其余参考走 Ref2VA 自由参考槽(≤9 图/3 视频/3 音频)【文档】。

| 档位 | 张数 | 何时用 | 依据 |
|---|---|---|---|
| **默认:首帧 1 张(I2V)** | 1 | 一律从此档起步 | 实测排名 960P 直出 > 480P 直出 > 首尾帧版;一张好首帧是质量/速度最优解【实测】 |
| 进阶:首尾帧 2 张(FL2VA) | 2 | 仅当镜头有**明确结束状态**(人物回头/光线变化/运镜终点) | 首尾帧版最慢(测试台 14min);**首尾同帧≈静止**,尾帧必须带足变化量【实测】 |
| 候选抽卡:九宫格 | 9 选 1 | 构图没把握时批量出候选 | 官方/BigBanana/B站导演台三方印证;是**过程量**,选定 1 张进 Picture 槽【调研】;提示词模板见[九宫格候选抽卡提示词模板](./参考_提示词工程/九宫格候选抽卡提示词模板.md);整版故事板直出=宫格另一义,见五节 |

两条补充:

- **一致性参考不占 Picture 槽**:定妆照/场景图走 Ref2VA 自由参考槽(JZL `@素材名` 调度模式,MIT 可参考)。
- **5s 镜不需要镜内中间关键帧**【裁定:124 帧/5s】;尾帧的另一用途是**段间末帧交接**——下一镜首帧直接取上一镜生成视频的末帧,不必提前画静态尾帧图。
- 同镜多人物时:每人 1 张干净单人定妆照作参考,勿用合影【既有裁定:参考图上限+多人物策略】。

## 三、超分结论:输入侧不需要甚至有害;输出侧已裁定砍掉

**给 H3 的首帧图预先超分 = 无益 + 有坑,不做**:

1. H3 在 **~1MP 空间**(默认 1344×768)生成,参考图被缩放到工作分辨率——超分多出的像素**不进生成**【文档:原生 ~1MP,更高只有时间/显存成本没有真细节】。
2. **超分后参考尺度错位 → 脸漂**(minimax-h3 技能故障表原文);latent 超分另有音频糊的坑(降 audio_denoise 缓解,推断性)【文档】。
3. 想让参考「喂得更重」的正确手段是**参考权重/占比**:官方 reference sizing 身份锁用 `max`;JZL 扩展 ref_scale 面积放大 1.0~5.0(match 模式)——是权重不是分辨率【文档+调研】。

**要区分两件易混的事**:K2 链上的 SeedVR2 **修复档**管首帧「**干净**」(参考图霉斑/脏斑治理,≤1MP 护栏,既有三档裁定)——干净首帧确实提高视频质量,但那是降噪修复不是放大。

**输出侧视频超分**:只提高播放清晰度,**不提高生成质量**(运动/一致性/音画不变,超分不改变生成内容)。已裁【09-14】:2K 砍掉、960P 直出生产档、480P 测试档;本地 SeedVR2 视频超分 VAE 分块 ~1.5h 是真瓶颈【实测】;官方 2K 路线本质是 hosted **regenerate**(重新生成)而非超分【文档】。

**已落实到工作流(09-14 同日执行)**:漫影单镜 H3 模板（`apps/frontend/lib/assist/image-studio/h3-shot-template.json`）已摘除全部超分机械——删浅空间放大两段式(`MinimaxH3LatentUpscaler3D`+LTXV 音视频分离/合并+精修采样器,共 15 节点)与 SeedVR2 注释,改为**单段直出**(ResolutionSelector 的按位 `megapixels=0.98` 为原生档，测试档为 0.2；`multiple=32`。具名字段残留值与 tiny_vae 漂移见[参数速查](./参数速查.md)，不得据此宣称两种模板均已统一);回归锁在 `h3-shot-video-workflow.test.ts`(禁 Upscaler/LTXV 分离合并节点+单采样器断言)。仓库只读 `2_视频/H3视频/3_超分后处理/社区-视频文件直接超分-SeedVR2.json` 保留为手动后处理入口,产线不再自动做。

## 四、对视频质量真正有杠杆的四件事(替代超分)

按杠杆率排序,实施时预算花在这里:

1. **干净的首帧**:K2 修复档治理脏斑/霉斑(≠放大)。
2. **一致性**:首帧与定妆照一致 + 定妆/场景走 Ref2VA 参考槽 + reference sizing `max`/ref_scale。
3. **官方格式提示词**:三字段/六节 + `<d>[语言]台词</d>` + 运镜受控词表(吸收分析 P0-1 builder 的职责)。
4. **正确档位**:960P 生产/480P 测试 + length 守 17k+5 网格 + 5s 内单镜一镜到底。

## 五、整版故事板直出(九/六宫格分镜)

**定位:一句话故事 → 整版故事板一次直出**。输入只要三行(谁/在哪/一句话),LLM 先自动扩写成完整起承转合(温情/搞笑/悬疑三选一,反转只一个)再拆格,Qwen-Image-2.1 **图像编辑**模型套空白宫格模板一次出整版:3×3 九宫格或 2×3 六宫格(3列×2行),一格一镜、从左到右从上到下按序读;切格后的单格=单镜首帧粗稿,「可直接喂 H3」【调研:10-04 B 站竞品工作流包拆解,BV1kKa36SEqb】。

**与第二节「候选抽卡:九宫格」是两种宫格语义,勿混**:抽卡=同一镜头出 9 个构图候选、选定 1 张进 Picture 槽(过程量;App 基建 `submitGridImageRequest`,apps/frontend/lib/ai/image-generator-grid.ts:35);整版故事板=9/6 格连成完整叙事、每格一个时刻——「每格一个主要信息、一个清晰瞬间，不在同一格叠加多个时间状态」。宫格数相同、用途正交:一个选优,一个铺叙事。

**机制五件(拆解坐实,照抄可复刻)**:

1. **模板图一图三用**:两张空白模板(九宫格 `九宫格_3x3_16x9_2MP_1920x1056.png`/六宫格 `六宫格_2x3_16x9_2MP_1920x1056.png`)同时占三个位置——①**参考图** image1 槽(「<image1>是空白九宫格模板：只定3×3网格结构与分隔线，不管内容」);②**布局锚**(网格结构与分隔线由此写进输出排版);③**切格基准+画布**(输出画布跟随模板尺寸,切格数字与模板配套)。image2/3/4 分给人物A/人物B/场景,一槽一职(同拼接锁「参考卡一卡一职」口径)。**件名陷阱(源包自身瑕疵)**:包内两张 png 是中文名,两版工作流 #110/#292 LoadImage 实际引用英文名 `grid_3x3_16x9_2MP_1920x1056.png`/`grid_2x3_16x9_2MP_1920x1056.png`,与使用说明「文件名不要改」自相矛盾——复刻时二选一对齐:png 改名成 grid_* 或改 LoadImage 引用,照包内名原样放 input 会对不上号。
2. **分隔线与切格边界逐像素对齐**:提示词侧钉死「格间细白线分隔，不越格不跨线，不缺格不重叠」;切格侧按整除边界切。原包尺寸链:画布=模板原生 1920×1056(2MP)→ VOSR2 ×2 → 3840×2112 → 切格单格 3×3=1280×704、2×3=1280×1056(3840÷3=1280;2112÷3=704、÷2=1056,整除零余)。换尺寸必须模板与切格数字配套改(原包对照:2MP→1920×1056 切 640×352;4MP→2688×1536 切 896×512,「倍数保持 96」)。
3. **恒 true 开关=画布钉死模板支路**:原工作流 #131 `ComfySwitchNode`(LATENT 二选一)恒 true——恒走模板图经文本编码器出的 latent 支路(「走编码器 latent = 模板尺寸 1920×1056，零偏移」),`EmptyLatentImage` 支路恒被旁路(同尺寸空 latent,丢模板锚)。语义=把「画布跟随模板」硬连线,不是留给用户的可配置分叉。同类还有九↔六总开关 #302:一个布尔同时拨模板/规则/切格高三处,「模板 / 规则 / 切格三处自动跟，不用动别处」。
4. **「超分=分辨率补偿」甄别口径**:原包的 VOSR2(外部插件 comfyui-vosr2,约 7G 模型;漫影自研链未用)作用是**把宫格直出的低清格补到可喂 H3 的分辨率**——整版 ×2 后切格,单格从 0.2~0.35MP 补到 ≈0.9~1.35MP(H3 工作分辨率 ~1MP 量级);**不是画质增强魔法**,不改变生成内容与细节上限。与第三节不冲突:第三节反对的是把参考拔到工作分辨率**之上**求画质(多出的像素不进生成);这里是把过小单格**补回**量级,属尺寸配套——嫌 ×2 链重也可按原包对照表直接换 4MP 模板给足画布,同样不必引 VOSR2。
5. **切格不必引外部插件**:原包用 `TTP_Image_Tile_Batch` 切格;漫影自研 `MyImageGridSplit`(apps/backend/engines/comfyui/my_nodes/nodes/my_image_grid_split.py:72)数学等价——floor 整除边界、行主序(对应原包「按行优先切 1..9」)、并集恰=原盒互不重叠、右/下边缘格吸收整除余数;且自带 **A5 版式防泄漏铁约束**(出口永远是切割后单格、宫格图绝不当视频参考,警示原文见[参考_拼接衔接锁与一致性锚点](./参考_拼接衔接锁与一致性锚点.md)四节)。

**漫影落点**:整版直出适合**分镜粗预览/节奏对拍**——一次出 9/6 镜全序,先看叙事节奏、人物一致性与风格走向,再决定哪些镜进单镜链精修;定稿首帧仍走第一节单镜链。宫格整图与切格单格入 H3 全程守 A5(宫格整图绝不作参考)。多宫格画幅比例自适应写法另见[Qwen-Image-2.1-文生图](./参考_提示词工程/Qwen-Image-2.1-文生图.md)「三视图 / 多宫格」节。
