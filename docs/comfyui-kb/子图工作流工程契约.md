## 零、铁律先行

**子图边界连线必须写 `inputs[].linkIds` / `outputs[].linkIds`。**
只在 `links` 数组里写带 `-10/-20` 端点的线 = 数据在、前端图引擎**不登记**:
线不渲染、转换拿不到子图输出、点生成直接报下游节点缺连接。

## 一、症状三连(同一根因,见到任何一个先查 linkIds)

1. **入口/出口圆点没有线**:双击进子图,左侧花括号处的 model/base 圆点(入口)或右侧(出口)后面零根线——不是没连,是没登记。
2. **主图点生成报缺连接**:如「KSampler - model 缺少连接」——graphToPrompt 解析不出子图输出,主图上明明画着线。
3. **行首节点看似连着**:loader 的 model 输入口 link 数据非空,但整条执行链在边界处断。

## 二、装载机理(前端 1.53 实证)

- 装载(configure)时按 **IO 槽的 linkIds** 把边界线登记进图引擎(独立于 JS 对象的权威存储);`sg.links` 的 -10/-20 线只是数据面。
- **linkIds 只在装载时读取**——在活图上补 `slot.linkIds` 不触发登记(实测无效),必须改文件后重开工作流。
- IO 节点(-10/-20)**不在**子图 `_nodes` 里;子图实例本身就是 LGraph(`_nodes`/`links`(Map)/`inputNode`/`outputNode`)。
- 渲染与 prompt 转换都走图引擎登记面,不走 sg.links 裸数据——所以「文件里线都在」与「画布没线+报错」可以同时成立。

## 三、诊断配方(三关,别只看文件或截图)

1. **文件面**:数 `sg.links` 里 origin_id=-10 的线数(应=入口槽数×各自扇出);查 `inputs[].linkIds` 是否为空。
2. **转换面(判生死)**:Playwright 装载后 `await app.graphToPrompt()`,看目标节点 `output['12'].inputs.model`——缺失=坏;`["90:1",0]` 这类子图内部引用=好。
   - **坑:loadGraphData 注入成功 ≠ 用户点生成能过**——验证必须跑转换路(graphToPrompt 干跑),这是 09-21 之前测试盲区的教训。
3. **视觉面**:`app.canvas.openSubgraph(node90.subgraph)`(**方法在 canvas 上,不在 graph 上**)→ `centerOnNode(sg.inputNode)` → 截图看圆点后有无扇形线。

## 五、JSON 形状速记(前端 1.53)

```
definitions.subgraphs[] = {
  id(uuid), version, revision, state{lastNodeId,lastLinkId,...},
  config{defaultIOState}, name,
  inputNode:  {id:-10, bounding:[x,y,w,h]},   # 锚=边界实体,圆点画在槽 pos
  outputNode: {id:-20, bounding:[x,y,w,h]},
  inputs:  [{id:uuid, name:"model", type:"MODEL", linkIds:[...], pos:[x,y]}],
  outputs: [{id:uuid, name:"model", type:"MODEL", linkIds:[...], pos:[x,y]}],
  widgets:[...],            # 子图级 widget 初值
  nodes:[...],              # 内部节点(不含 -10/-20)
  links:[{id, origin_id, origin_slot, target_id, target_slot, type}],  # 对象格式;-10/-20 可做端点
}
```

- 前端自己再保存会重序列化(version→1、内部 id 重编、槽位补 linkIds/pos)——linkIds 随活图登记面走,属正常。
- 主图上的宿主节点:`type`=子图 uuid,`properties.subgraph`=同 uuid;干跑转换时其内部节点以 `宿主id:内部id` 展开(如 `90:101`)。

## 五点五、第三根因(同日 10:58 第二炸,已根治)

**前端装载会重排节点槽序、连线按槽位序号落座**——文件里 MyDaojieRoute 槽序若按服务端习惯写
(base 在首位),装载瞬间整排错一位:base 收 MODEL、九型槽收 COMBO,服务端拒
「Return type mismatch」。**文件必须按「装载稳定序」写:九型在前、base 末位。**

**服务端组合框列表输入不吃 COMBO 链接**:子图边界必然把外部 [80].base 以链接形态
(received_type="COMBO")转进来,而组合框列表输入的 input_type=列表字符串 → 必拒。
**吃链接的组合框输入声明成裸 `("COMBO",)`**(值层不变;宿主侧用户下拉由子图
inputs[].type_data 提供)。历史成功单从未让组合框吃链接——旧链路 base 是纯值。

回归网:`my_nodes/tests/test_workflow_subgraph_contract.py` 三道
(IO linkIds 登记 / 路由槽名+槽序+base 裸 COMBO 型+类型对拍 / 九行与 daojie_lora_stack.json
单源一比一),外加**服务端验证门**:Playwright loadGraphData→graphToPrompt→POST /prompt
看 node_errors(400/含 node_errors=拒;200 零 errors=过,注意及时 DELETE /queue 取消)。
**前端转换过 ≠ 服务端验证过,两者都必须跑。**
