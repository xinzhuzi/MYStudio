# 分镜×H3 视频产线(单镜 5s 真动态视频)

2026-09-14 立线并实弹出片。本文=这条产线的**架构定位、规格裁定、实测数据与坑清单**的真源;改采样参数前另查[参数速查](./参数速查.md),工作流库盘点另查[漫影工作流清单](./漫影工作流清单.md),分镜图(输入侧)另查[分镜图生成与超分指引](./分镜图生成与超分指引.md)。

标注三态:【实测】= 本机跑过、有日志可查;【文档】= 技能/官方文档原文;【裁定】= 用户拍板、有原话在档。

## 一、四层流水线定位:H3 与 remotion / hy / video-use 的关系

**H3 不替代任何既有层,它是素材生产层的升级**——把"静帧+Remotion 伪运动"换成"每镜 5s 真动态片+画内声"。分工:

```
H3(素材生成层,新建)—— 每镜 5.167s 真动态画面+画内声(音画同炉)
   ↓ 产出装进
remotion(组装渲染层,既有)—— current.mp4 槽+时间线+转场+字幕+混音+导出
   ↑ 叠 alpha overlay            ↑ 打包 EDL
hy:hyperframes(装饰层,既有)   video-use(成片使用层,既有)
```

| 层 | 职责(实证) | H3 上位后的变化 |
|---|---|---|
| H3 | 每镜真片生成 | 新增的源头 |
| remotion | 组装/渲染(`electron/rendering/plugins/remotion/`;合成层 `VisualClip` 视频镜=原生 `OffthreadVideo`,不静音即出声) | 职责变纯:内部"静帧 Ken Burns/3D 伪运动"段被 H3 接走,降级为兜底 |
| hy(hyperframes) | 渲染 1920×1080 带 alpha 的 overlay.mov(prores-4444),氛围/遮挡/装饰叠加,按 r86/r88 版本化(`hyperframes/{章}/r{N}/`) | 完全互补且价值放大:雨雾粒子叠真动态画面才是电影感;零冲突 |
| video-use | 每镜"最终视频+音频+台词+时长"打包成 editable-edl 带 sha 溯源(`video-use/{章}/r{N}/video-use-run.json`) | 完全互补:协议零改动,输入自动从伪变真;`pad-video-to-audio` 策略继续适用 |

【实测】道劫 r88 的 video-use 载荷:`videoPath` 指向 `remotion/outputs/shots/.../current.mp4`、`audioPath` 指向 TTS wav、`durationUs=5133333`——下游协议早就在等每镜真片,只是 current.mp4 里此前装的是静帧伪视频。

【裁定】09-14 晚架构定调(用户原话方向):「未来视频线=H3 生成视频,Remotion 只组装 H3 产的片段(拼接/字幕/音频),图片作为 H3 的输入」。

## 二、一镜 5s:帧数网格与时长真源

- 帧数恒在 **17k+5 网格**(`length mod 17 == 5`),训练区间 124–362 帧【文档】。
- **124 帧=5.167s@24fps=训练区最小档**,"一镜 5s"即 H3 的标准单位【实测】。
- 名义秒数→帧数**向上吸附**:`length = 17*ceil(max(0, ceil(d*24)-5)/17)+5`,clamp [124,362]:5s→124、6s→158、8s→192(整)、12s→289、15s→362 封顶,超 15s 截 362。
- **排轨按帧数真实时长(5.167s),不信分镜表名义整数秒**【裁定】;工作流内由公式节点(`ComfyMathExpression: max(5, round(a*24)) + (5 - …%17)) %17`)自动吸附,人类入口只有秒数节点。
- Remotion 合成 30fps:H3 片 24fps 经 `OffthreadVideo` 自动帧率映射,但**轨道长度必须按真实时长换算**(5.167s→30fps 合成 155 帧)。

## 三、分辨率与清晰度裁定

| 档位 | 分辨率 | 成本(5s/条) | 用途 |
|---|---|---|---|
| 480P 直出 | 608×352(selector 0.2) | **全链 334s**【实测】 | 策略测试档(音频对比/运动草稿,耳朵在听不在看) |
| **960P 直出(单段原生)** | 1344×768(selector 0.98) | **21m07s**【实测】 | 生产+交付档,一站到底 |
| 2K(SeedVR2 超分) | — | — | **已砍**(09-14 裁定:时间过长;超分工作流留库不进管线) |

- **超分不进工作流**【裁定,原话「不要让工作流做超分了」】:两段精修(480P 生成→LatentUpscaler3D→960P 精修)本质是 latent 超分,已从模板摘除;终态=单段直出 31 节点。
- 清晰度四件套(缺一即"960P 还是糊"):生成原生档+关键帧同画幅原生出+导出 CRF≤18+全链路零中转缩放。**导出码率是第一嫌疑人**。
- 关键帧(=H3 首帧)必须全尺寸原图:K2 出图原生 1MP(16:9≈1360×768)≈H3 输入甜点,天然直连零预超分【裁定+实测】;**I2V 细节上限=首帧,首帧软全镜软**。

## 四、音频归属:测试矩阵(不拍板,全手段保留)

用户裁定(09-14):需要大量实测才能定,且预判视频线吃不下全部音频(音色不可控/台词易糊/音乐粗粒度)。三个正交开关:

- 生成侧 `audioPolicy`:`ambient`(默认:声场+画内声,声明无对白唇闭合)/`full`(台词 `<d>[Chinese]` 包词+说话人+旁白 off-screen 措辞)/`bare`(最小声场)——已实现在组装器 `h3-shot-prompt.ts`。
- 生成侧 `frameMode`:`i2v` 单帧(默认)/`fl2va` 首尾双帧(锁构图;坑见 §七)。
- 混音侧三档(裁判位,09-14 已落 Remotion 组装层):`h3-baked`(用烤进 MP4 的音,该镜 TTS/SFX 不再重复挂载)/`tts-stack`(视频静音+TTS 人声+音效+音乐轨,缺省且保持旧行为)/`mixed`(H3 环境声垫底+TTS 人声在上,视频音量从 `H3_MIX_VOLUME=0.35` 起步)。选择器只对 `mediaRef.kind=video` 的镜开放,图镜恒按 `tts-stack`。

| 混音档 | H3 视频镜 | 该镜 TTS/SFX | 面板文案 |
|---|---|---|---|
| `h3-baked` | 有声,音量 1 | 不挂载 | 用片内声 |
| `tts-stack`(默认) | 静音 | 照常挂载 | 配音主导 |
| `mixed` | 有声,音量 0.35 | 照常挂载,既有 voice ducking 生效 | 双层混音 |

`H3_MIX_VOLUME` 是可调裁判参数,当前只作起步值,须由固定三镜试听矩阵实测后再拍板。回收消费器在 `studio-probe-media-evidence` 主进程 ffprobe 可用时把真实时长(微秒)写入 `StoryboardItem.h3DurationUs`;探测桥不可用或失败时静默降级为名义时长,不影响 R1/R2。

测试省钱法:480P+固定三镜测试小队(纯旁白/双人对白/无台词动作戏);一条 H3 片三种混法并排听(生成一次完成三组对比)。

## 六、存储落位与回收链(已实施,09-14-h3-video-writeback)

**引擎 output 是暗房,项目目录才是家。** 单镜视频家(既有契约,`remotion-current-paths.ts` 单源):`<项目根>/remotion/outputs/shots/{章}/{镜id}/`;H3 片落其下 `h3/` 子夹,不动 Remotion 的 `current.mp4` 语义(两线并存)。

回收链全链(照抄图像线范式,载荷换视频):

```
SaveVideo(三段式前缀 video/漫影/{chapterId}/{shotId}/{policy})
  → SaveVideo.video 直通输出 → ManyingShot.video 槽(生成器注入连线;执行顺序保证)
  → ManyingShot.run:glob 引擎 output 最新 mp4(shot_id 字符白名单+64MB 上限)→ b64
  → POST sidecar /comfy/bridge/writeback(imageB64/videoB64 二选一)→ 收件箱落盘(重启不丢)
  → 宿主 consumeComfyBridgeWritebacks 视频分支(5s 轮询):
    parseShotTarget → subfolder 白名单复核(精确匹配 video/漫影/{episodeId}/{shotId})
    → writeProjectBinary 落 remotion/outputs/shots/{章}/{镜}/h3/{policy}_v{n}_{ts}.mp4
    → 主进程 ffprobe 实测 duration → updateStoryboard(mediaRef=video + h3DurationUs(可选) + outputVersion+1 + videoCandidates 追加 provider "h3-comfyui"+policy 标签)
    → 失败不 ack,下次重试(语义同图像线)
```

关键裁定:

- **三段式前缀=回收白名单**(双侧:节点 glob+消费器复核):旧前缀 `video/漫影_S{NN}`、用户自存 `video/ComfyUI` 不误收;旧前缀产物需人工安置(首例=S01 孤片,已落 `IP/MA/remotion/outputs/shots/chapter-001/sb-chapter-001-001/h3/ambient_v1_20260914-131836.mp4`)。
- **mediaRef 语义(H3 时代)**:`mediaRef`=「当前视觉资产」(可为 video),`keyframes[0]`=首帧图;视频只存 videoCandidates(多候选拍带 policy 标签),**关键帧操作不再把 video mediaRef 打回图**(storyboard-slice I1 守卫,09-14 深审修正)。
- 收件箱消费时机:画布 tab 在场才轮询(同图像线);app 关闭期间的产物等下次开画布补收,不丢。

## 七、坑清单(实弹教训,勿重蹈)

| 坑 | 症状 | 处置 |
|---|---|---|
| `ModelPreviewOverrideKJ` 的 `tiny_vae='taeh3.safetensors'` | 引擎模型列表只有 `['none']`→/prompt 验证整图打回(Output will be ignored),表面像"提交了空图" | 模板锁 `none`+回归断言;排障先看引擎日志 validation 段,别信前端表象 |
| **BlockCacheT8 间歇崩 MPS** | 隔离引擎在"块缓存 refresh 边界"二连毙(首个 attention 步附近静默退出,exit 0 无 traceback);app 托管引擎+同参数实测可跑通(21m07s 成片即带 T8) | 隔离/自拉引擎跑 H3 若在 refresh 边界死=先 bypass 节点 48(去 T8);稳定性优先时直接去,吞吐优先时留(单步 5m25s→3m53s 的预热加速来自它) |
| 首尾同帧≈静止 | 同一张图喂 FL2VA 首/尾帧槽,5s 片近乎静止 | I2V 单图语义:尾帧槽不接;双帧留 fl2va 升级档且两帧必须有真实差异 |
| 引擎生死随 app | 用户关 app→孤儿看门狗回收引擎;开 app→礼送(SIGTERM exit 0)既有实例 | 长跑挑 app 关闭窗口,或用 app 自己的引擎(端口账本轮换,真源=引擎进程 `--port` 参数) |
| 前端入队前画布旧图残留 | `openWorkflow(entry)` 后画布仍是旧图,queuePrompt 会**误排别人的工作流** | 必须 `openWorkflow(entry)` 后补 `loadGraphData(activeState, true, true, entry)`,且入队前断言节点数(31)+I2V 在场 |

| vitest 裸跑 apps/frontend | 24 文件假败(cwd/config 全歪) | 恒从 `apps/` 起+`--config frontend/config/vite.config.ts` |

## 八、实测账本

- 单段直出 0.98 原生档(M4 128G,turbo4step+SolAttn+BlockCacheT8):**21m07s/5s 片**——装载 ~3-4min(38GB UNET+16GB TE+5GB VAE,冷启动才发生)+采样 17m08s(4 步,单步 5m25s→3m53s 随 BlockCache 预热加速)+解码封装 <1min。
- 0.2 测试档(608×352):**全链 334s** 出片 5.17s 双声道 AAC——两档生成法(测试档运动草稿→生产档正片)的经济学基础。
- 推算:连续出片(模型驻留)~17-18min/条;一章 30 镜一次队列 ≈8.5-9h 过夜批。
- 对照:被砍的两段式 960P 线 18m13s/条——比单段还略快,吞吐不够时可拿此数据重新拍板。

## 九、更优配合策略(09-14 讨论,候补实验项)

1. **镜级→场级生成**:H3 提示词原生一段多镜(`[Shot 1]…[Shot 2] At 00:04.500…`+CUT TO),训练区 5-15s 装下一场 2-3 镜——场内连贯性白送+省冷开销;分镜表已有场结构。镜级作精修档并存。
2. **末帧交接**:跨场/动作衔接镜用上一镜视频末帧做下一镜首帧(成片抽帧,不用 K2 图);场内一次生成、场间末帧交接互补。代价=链式串行,过夜批无碍。
3. **两档生成法**:0.2 档 334s 出运动草稿→人审动效→0.98 档正片;重拍率>~35% 时总耗时更划算,且草稿与音频矩阵试听共用。
4. **Ref2VA 身份直挂**(09-14-h3-ref2va-line 已造):定妆照/场景图挂参考口,跨镜一致性由模型保证。
5. **candidates-first+24fps 对齐**:H3 线原生写 videoCandidates;合成帧率切 24 免帧率映射(上量前定)。
