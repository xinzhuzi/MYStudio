## 一、四层流水线定位:H3 与 remotion / hy / video-use 的关系

**H3 不替代任何既有层,它是素材生产层的升级**——把"静帧+Remotion 伪运动"换成"每镜 5s 真动态片+画内声"。分工:

```
H3 生成单镜素材 → Remotion shots 写 current.mp4
   → video-use 生成可审阅的章节 EDL
   → 用户确认 → HyperFrames 装饰与 EditingProject 投影
   → Remotion 章节渲染 → QC / 导出
```

| 层 | 职责(实证) | H3 上位后的变化 |
|---|---|---|
| H3 | 每镜真片生成 | 新增的源头 |
| remotion | 组装/渲染(`electron/rendering/plugins/remotion/`;合成层 `VisualClip` 视频镜=原生 `OffthreadVideo`,不静音即出声) | 职责变纯:内部"静帧 Ken Burns/3D 伪运动"段被 H3 接走,降级为兜底 |
| hy(hyperframes) | 渲染 1920×1080 带 alpha 的 overlay.mov(prores-4444),氛围/遮挡/装饰叠加,按 r86/r88 版本化(`hyperframes/{章}/r{N}/`) | 完全互补且价值放大:雨雾粒子叠真动态画面才是电影感;零冲突 |
| video-use | 每镜"最终视频+音频+台词+时长"打包成 editable-edl 带 sha 溯源(`video-use/{章}/r{N}/video-use-run.json`) | 完全互补:协议零改动,输入自动从伪变真;`pad-video-to-audio` 策略继续适用 |

【实测】道劫 r88 的 video-use 载荷:`videoPath` 指向 `remotion/outputs/shots/.../current.mp4`、`audioPath` 指向 TTS wav、`durationUs=5133333`——下游协议早就在等每镜真片,只是 current.mp4 里此前装的是静帧伪视频。

【裁定】09-14 晚架构定调(用户原话方向):「未来视频线=H3 生成视频,Remotion 只组装 H3 产的片段(拼接/字幕/音频),图片作为 H3 的输入」。

## 二、一镜 5s:帧数网格与时长真源

- 帧数恒在 **17k+5 网格**(`length mod 17 == 5`),训练区间 124–362 帧【文档】。
- **124 帧=5.167s@24fps=训练区最小档**,"一镜 5s"即 H3 的标准单位【实测】。
- 名义秒数→帧数**向上吸附**:`length = 17*ceil(max(0, ceil(d*24)-5)/17)+5`,clamp [124,362]:5s→124、6s→158、8s→192(整)、12s→294、15s→362 封顶,超 15s 截 362。(10-04 勘正:12s 档原误记 289,289 mod 17=0 违反 17k+5 网格;按公式自算=294,与 h3-prompt-writing/references/direct-zh.md 帧数表 12|294 一致。) 任意秒数**直乘 fps 会踩非法值**:网格合法性只由 17k+5 决定,与 fps 无关——fps 只用于排轨换算与音频同步(2026-10-25 AutoContext 调研补注,机制见 §九.五)。
- **排轨按帧数真实时长(5.167s),不信分镜表名义整数秒**【裁定】;工作流内由公式节点(`ComfyMathExpression: max(5, round(a*24)) + (5 - …%17)) %17`)自动吸附,人类入口只有秒数节点。
- Remotion 合成 30fps:H3 片 24fps 经 `OffthreadVideo` 自动帧率映射,但**轨道长度必须按真实时长换算**(5.167s→30fps 合成 155 帧)。

### 三采复刻二轮配方(1104 横役 R7,3/3 臂出片;思路源=班长三采,不装其件)

**QC 是体检不是门禁**这条铁律在此层不破:供给自检不许把别的行改成 fail。

**骨干② 逐镜期望(chapter-qc-expectations.ts)**:6 个断言键 `motion`/`speech`/`subtitle`/`cast-visible`/`face-readable`/`duration-in-target`,每镜每键三态 `expected`/`forbidden`/`unknown`。
真源全在分镜 store:`shotSemantics{cameraMove,actionIn/actionOut,visibleCharacters,personFree,shotSize}`、`continuityState{dialogueText}`、`shotFx.motion`(闭集 `LegacyMotionId`,**`"hold"`=明写定格**⇒该镜 motion=forbidden)、`durationTarget`。
裁定:**"分镜没记"≠"不该成立"**——`unknown` 计入缺证,`assertionCoverage` 逐键出三态计数上板;`motion-plan-consistent` 在"零镜声明要动"时直接 unverified(伪动态门没有对照对象),不许拿全片均值冒充逐镜判定。

**骨干③④ 标定与打分(chapter-qc-calibration.ts)**:7 条信号 `aesthetic.fused`/`motion.tiMean`/`motion.staticFrameRatio`/`speech.coverageRatio`/`speech.secondsPerDeclaredShot`/`visual.blurMean`/`face.readableRatio`,各带越限方向(low-bad/high-bad)与 **σ 绝对护栏**(如 fused 0.05、TI 1.0、静止占比 0.1——一簇几乎相同的样本不许把带画得比测量噪声还窄)。
阈值 = **本系列实测 mean ∓ max(2σ, guard)**(`signalThreshold`);`QC_CALIBRATION_MIN_SAMPLES = 5`,不足 ⇒ `uncalibrated`,**相关行只能 unverified 且写明"样本 N 条,须 ≥5 条"**。
落盘 `<remotionWorkspace>/qc/calibration/{seriesId}.json`(seriesId 暂= projectId),**样本按 (章, 信号) 一条**:同章重跑覆盖不累积,样本数随章数长——这也是全链测里"重跑后 `countSignalSamples` 仍 1"钉住的口径。
单样本也入账(mean=该值、σ=0、sampleCount=1):板上"差几条才够标定"得有真数,不许报 0 条。缺件/坏 JSON/schemaVersion≠1 ⇒ 空库(降级不炸);路径含 `..`/非法字符直接抛(防系列 id 逃逸出 qc 目录)。
`scoreDimensionBoard`:**只有 pass 计分**,unverified 不给分也不倒扣(缺证的代价是不放行,不是负分),扣分按权重降序;`scoreCalibrationSet` 留给打标集算绿召回/红捕获。
**标定是结构性的,不靠各 assessor 自觉**:注册表每条要标定的行都绑 `calibrationSignals`,解释器出板后过 `calibrationBlocker`——没有可用带就把 pass 压回 unverified 并写明「哪条信号样本 n/5 条」。

**UI(chapter-qc 体检单)**:板改为**注册表驱动分组**——行的顺序/类别/权重/评价器名全来自真源,报告只提供三态;报告里出现注册表外的 id 会显式警示"注册表外 N 行"(防两侧真源漂移),注册表里有而报告没跑的行**不凭空造行**。
三行状态条压进板头:供给 `n 项:缺料 x · 硬矛盾 y`(逐条明细进 title)、逐镜期望 `N 镜 · 未声明 M 项`(title=逐键三态)、信号标定 `最高 k/5 条 · 打标集 c 条`(title=逐信号 mean±σ/样本数);行尾带越限镜序号 `#3 #7` 与权重数字。

**三条只有接线后才知道的读数(本批实弹)**:
1. **旧 10 行恒缺证,一半是"没供给"不是"没检测器"**(供给测里钉住的形状,非真章跑数):`declaredShotCount=0` 一章,`shot-spans`/`shot-readiness`/`reference-assets`/`frame-material`/`expectations-declared` 五连 gap——
   逐镜期望、语义、角色、文字、跨镜这五行多模态/期望类行**必然** unverified。故先让供给可见(报告里显式写"零镜区间是因为没声明,不是因为片子没问题"),再谈加检测器,否则新门只是把同一处缺证换个名字。
2. **`requiresCalibration` 不能只是句注释**:接完才发现全仓没有通用门——强制全靠各 assessor 自己记得调 `calibrationFor`,新加一行忘了查就**静默变绿**。
   补成结构性的:`calibrationSignals`(本行实际消费哪几条信号)+ `calibrationBlocker()`(要标定的行没有可用带 ⇒ 把 pass 压回 unverified 并写明「X 样本 n/5 条」;没绑信号则直接拦)。
   **只兜 pass 不兜 fail**——绝对码越限是真问题,拿"没标定"把它压回缺证等于藏病。注册表自检测再加一条:4 条要标定的行(`speech-integrity`/`real-motion`/`motion-plan-consistent`/`aesthetic-in-baseline`)每条都绑了真信号,不要标定的行不许偷偷绑。
