## 三、技术收敛点(全网已收敛的答案)

1. **衔接三路线**(所有工具必居其一):
   - **尾帧硬锁接力**:前段末帧钉为后段首帧(ChainDirector/AutoChain/Star7)——最粗暴最稳的基线
   - **latent 连续性**:Motion-Context 式 latent 直切尾帧+音频回够窗;Continuum 原生 AV latent;obvpm latent 拼接——社区口碑最好的高档位
   - **单次生成内多镜头**:官方提示词协议本身支持 SHOT 1/2/CUT 写法单 pass 消化;Multishot/Coverage/官方 Multiframe AddGuide 锚点
2. **17k+5 帧格对齐**:所有分段工具都做(resolution/length 贴 H3 网格)——我方 multiseg 已同构
3. **重拍管理三先例**(4125×40 规模的直接答案):Extender 段校验锁+级联失效 / SequenceForge 逐段 latent 存档+任意段重拍不级联 / Director-Cut-Studio 只重生成被改段
4. **角色一致性事实标准**:全部走 R2V 参考图通道+角色套图(角色卡),无人做跨镜自动 QA;RefMods(免训练 mod 文件)便利但有细节丢失争议;六段式提示词工程(abhi199424)=单镜多主体点名控制的可移植资产
5. **三大公认未解**(Reddit 共识,勿踩):跨代真一镜到底累积劣化(VAE 压缩/色彩漂移,~45s/4-5 段后明显,无人解决);generation 内部 cut 后身份漂移(需在精确 cut 窗口查脸);H3 人声音频质量差
6. **最强趋势信号**:社区从「找现成工作流」转向「coding agent+ComfyUI API 自建管线」(最高赞答案)——**直接印证我方 App+组装器路线;同时提示纯节点封装黑盒已引发反感**

## 五、可吸收清单(按价值排序,候令)

1. **Motion-Context 衔接原语**(1363⭐,GPL):latent 直切尾帧+音频回够窗+Save/Load Latent 跨运行+HTTP API。**必读参照**——若自研「上一镜尾帧喂下一镜」,其机制文档+Seam Probe 接缝量化直接对标;HTTP API 形态适配我方 App→引擎驱动。
2. **段校验锁+级联失效**(Extender/SequenceForge/Director-Cut-Studio 三先例):我方 4125×40 重拍管理的现成答案——已审批镜锁定不重掷、上游变更才级联。与我方 stale/sourceFingerprint 机制同型,吸收=把「按镜抽卡重开」升格为「校验锁语义」。
3. **obvpm timeline 语义**(Reddit 口碑王):latent 级 Extend/Bridge/Cut/cut 后从切口续;「scene planning:规划 prompts+clip 长度+队列过夜跑」是用户最想要而它没有的——**恰是我方章流水线已有的**,补上衔接层即可超越。
4. **六段式提示词工程**(abhi199424 multiref):单镜多主体 subject_definitions 点名+各自 retention strength;补 H3-Context-IR 未开源缺口。可直接进 h3-prompt-writing 技能。
5. **JZL/AIMixer 官方提示词协议复刻**:剧本→官方六段 Ref2VA 提示词+素材槽位调度全自动(136⭐ B站 5 万+播放验证);我方 h3-shot-prompt 已同构大半,可对照补缺。
6. **BFSNodes Shot Planner 范式**:拆成品视频(PySceneDetect)→列表输出→下游逐镜重生成——「成品→重制」入口我方没有(对照 viggle_remake 经验)。
7. **Director-Cut-Studio**(同形竞品):桌面 App 驱动远端 ComfyUI,其 Smart Long Render 缓存策略逐条对拍我方批量器。
8. **教训三条免踩**:真一镜到底别追(无人解决,2-3 段连续后就该切);RefMods 式便利件有细节丢失争议;黑盒巨石节点包已引发社区反感(我方架构反而踩在趋势上)。

## 七、结论
