## 一、定位与术语边界(先读)

本件是**参考资料**,不是 MYStudio 功能承诺——口径同 `docs/prompts/README.md:11`「官方/社区摘录与美学素材是参考文本，不是 MYStudio 功能承诺」【文档】。

**「九宫格」在本仓有两义,混写即事故**:

- **① 表情差分九宫格 = 一图九格资产型**:同一人九种表情,宫格本身就是交付资产。证据:`docs/prompts/道劫_九型配方.md:21` 表情差分行画幅列「1:1·4.2 九宫格」「2096×2096」;提示词开篇 `docs/prompts/道劫_底座节点_0918.md:73`「一幅三行三列的九宫格，每格是同一个人的一种表情，半身入画。」
- **② 九宫格候选抽卡 = 九图选一过程量**:宫格只是批量出候选的中间产物,切格后才可用,宫格版式绝不进成片。证据:`docs/comfyui-kb/分镜图生成与超分指引.md:28`「候选抽卡:九宫格」行——「9 选 1」「构图没把握时批量出候选」「是**过程量**,选定 1 张进 Picture 槽」。

配套坑警示【文档】:「宫格图直接当视频/生成的参考图，模型会把"宫格版式本身"带进成片」(`docs/comfyui-kb/参考_拼接衔接锁与一致性锚点.md:53`);正解同文 :55:「宫格**只作中间产物**：一次生成多镜概念图 → **切割成独立单图后**，单图再作参考/关键帧」。

源工作流属**第三义:整版故事板直出(本件主题,≠②义的九图选一)**——一张整版宫格=9 个连续节拍、一格一镜连成叙事,`#140` 切格后每格即该镜首帧粗稿,独立成镜喂 H3;与①义的最终资产(表情差分表)、②义的同镜九选一均不同。区分轴同 `docs/comfyui-kb/分镜图生成与超分指引.md:59` 五节:「宫格数相同、用途正交:一个选优,一个铺叙事」(抽卡=选优;故事板=铺叙事)。本件标题挂「候选抽卡」系任务指定路径,内容实为整版故事板模板——§三两套模板的「9 格剧情」「6 格剧情」段即逐格叙事枚举,非同镜候选。

```text

- <image3>只定人物B身份：同上，必须与A一眼可区分。
- <image4>只定场景：空间结构、陈设、光线时段。

- 每格写清：出场人物+位置朝向、景别机位、动作、表情视线、本格剧情信息。

【排版与排除项】
- 输出一张 3×3 九宫格，9 格从左到右、从上到下读，格间细白线分隔，不越格不跨线，不缺格不重叠。

```

## 四、故事大纲(#243)写法:三行种子

输入只写三行,起承转合全部交给 LLM 扩写(归纳自源包便签 #278「故事大纲怎么写（必读）」):

| 行 | 写什么 |
|---|---|
| 谁 | 出场角色+一句话特征 |
| 在哪 | 场景一句话 |
| 一句话 | 故事大概 |

关键句逐字(便签 #278):「填 #243，三行：」「起承转合不用写，Qwen自动扩写（温情/搞笑/悬疑贴合主题三选一，反转只一个，落点收住）。」

节点 #243 当前示例(逐字):「谁：猫、老鼠」「在哪：厨房」「一句话：两个吃货 第一次分吃一块奶酪」

扩写三向(模板【种子扩写】段,全文见 §三):温情向「相遇→小冲突→意外→和解」、搞笑向「追逐→倒霉→反杀→和好」、悬疑向「平静→异样→揭秘→反转」;反转有且只能有一个,落点必须收住;扩写过程不输出,只输出最终提示词。

## 五、轴线规则与成品结构的设计意图

**轴线规则**(模板【全局一致性】段原文):「轴线：双人同框先定A左B右（或A右B左）+各自视线方向+摄像机在哪一侧；正反打、过肩不许越轴，9 格屏幕方向保持一致。」

设计意图(归纳):把电影 180° 轴线规则提示词化。宫格是连环读的——相邻格若人物左右站位、视线方向乱跳,切格成镜后拼起来就是越轴废片;写死「先定A左B右（或A右B左）+各自视线方向+摄像机在哪一侧」,9 格屏幕方向恒定,切格后任意相邻两格可直接当正反打用。六宫格版同款,仅把「9 格」写成「6 格」。

**成品提示词结构**(由 #265 六宫格成品示例归纳):两段式——

| 段 | 管什么 | 写什么 |
|---|---|---|
| 全局设定段(一段) | 跨格恒定项 | 场景(空间/陈设/光线时段)+人物A/B外观;一次锁死,逐格不复述 |
| 逐格段(每格一段) | 本格增量 | 景别机位+站位朝向+动作+表情视线+本格剧情信息 |

成品开篇逐字(#265):「一张2×3六宫格漫画分镜（3列×2行），格间细白线分隔，无文字、无水印、无编号。」全局段起首=「全局设定：温馨明亮的卡通厨房」。

设计意图(归纳):全局段=一致性锚点,身份/场景/光线只写一次、全格共享;逐格段=纯增量差异,一格一节拍,不叠时间状态——与仓内「身份锚点捐赠」「参考卡一卡一职」纪律同构(`docs/comfyui-kb/参考_拼接衔接锁与一致性锚点.md:45-47`)【文档】。【参考素材职责】段的「（各管各，不许混用）」就是一图一职在多图输入下的写法;「A、B的脸和衣服不许互换，不许多出第三个人」加外形相近时每格重复可见区分点,治理的是双人宫格最常见的一致性失效(串脸/多人)。

## 六、若要在本仓落地(本地化近路)

**四件不装,一句话**:ttp_toolset(源包切格件 `TTP_Image_Tile_Batch`)、llama-TE(源包本地 LLM 反推件,仓 `comfyUI-llama-TE`,节点 `QwenTE_*`,搭约 15G 本地 LLM)、ComfyUI-Prompt-Assistant(提示词小助手——「API 版工作流里的反推节点就是它家的」,`01-提示词小助手安装.md:3`;即 API 版 `#310` ImageCaptionNode)、VOSR2(放大,约 7G)一件都不装——四职能本仓各有正路:切格有 `my_nodes/my_image_grid_split`(`docs/comfyui-kb/参考_拼接衔接锁与一致性锚点.md:58`,0929 落地)与 App 侧九宫格合并生成基建(`apps/frontend/lib/ai/image-generator-grid.ts:35`「Used by merged generation (九宫格) and quad grid (四宫格) in director and sclass panels.」,director/sclass 面板用);LLM 扩写走 App 侧模型路由,不须引擎内嵌本地 LLM、亦不须在线反推件;放大在 H3 输入侧已裁定不做(`docs/comfyui-kb/分镜图生成与超分指引.md:36`「超分结论:输入侧不需要甚至有害」)。

**正路(真要落地时)**:照三视图型先例立新「型」或进工作流库社区模板位,零新插件——

1. 先例:道劫三视图型=「`resolution_override` 直填」3072×1024 拼板一次生成,后处理「裁格;[80] WIDTH/HEIGHT 直出,[61] 退位旁路」(`docs/prompts/道劫_九型配方.md:18`)——拼板+自动化宽高+裁格,全程仓库既有件。
2. 落位:新「型」=道劫九型配方表加行;或社区模板进工作流库对应域功能子夹。提示词网格枚举=逐格文案与格位一一对应(§三模板的【9 格剧情】/【6 格剧情】段即枚举格式)。
