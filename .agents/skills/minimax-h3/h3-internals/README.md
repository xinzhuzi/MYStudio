## 执行摘要

这个视频用「演化叙事」讲透 H3 工作流的来龙去脉：所有 H3 工作流都可拆成**输入→理解→采样→解码**四步；
社区一切优化都在回答三个问题（省显存 / 更快 / 画面更好）。最有价值的三个认知纠偏：

1. **直接砍采样步数必然糊**——模型训练时步数就烙在权重里（官方 20 步），4/8 步加速 LoRA 的本质是
   「拿官方 20 步产出当老师、只用 4/8 步训练」的蒸馏件，与主模型只差约 1% 权重，所以能做成挂件。
2. **二采是提速手段，不是超分**——第二次采样本来就是目标分辨率，只是把前半程（本来模糊的轮廓期）
   换到低分辨率跑，中间用一个训练出来的 latent 放大模型桥接。目标分辨率本来就低（≈0.5MP）就不需要二采。
3. **「SelfLift 二采低显存兼容版」是社区主流终态**——SelfLift 节点把「latent 放大+二采」打包，
   但它自带的 SelfLift 加速算法实测又慢又差，社区共识 rho=0 关掉它退化为纯二采；
   再叠官方核心的两个注意力节点（dense 后端 + Sol-Attn 稀疏注意力）和 KJNodes 显存切块。

适合谁：能跑通 H3 工作流但看不懂社区工作流在改什么的人。看完能对着任意新工作流判断它改了哪一层。
