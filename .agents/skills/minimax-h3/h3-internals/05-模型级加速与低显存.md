# 05 · 模型级加速与低显存——注意力后端 / 稀疏注意力 / 显存切块

> 来源主题段 11:02–12:08。前面所有加速都在**采样**上做文章（步数、分辨率分段、σ），
> 本节在**模型执行**层面加速。

## 官方两个注意力节点 [t=11:08-11:26]

UP 主口径：主要用官方的两个节点——**ModelAttentionBackend** 与 **Model Sparse Attention**
（口播转写 "model attention back and model space attention"）——对应加载耳熟能详的
**SageAttention** 与 **Sol-Attn**；两个节点都是**通过优化 attention 机制降低模型计算量**，从而加速采样。

### 本机源码验尸（2026-11-07，Mac 引擎 ComfyUI 0.44.0）

**`ModelAttentionBackend`** —— `comfy_extras/nodes_model_advanced.py:405-457`，category `model/patch`（实验）：

- 后端选项只有两个：**`pytorch attention`** 与 **`comfy kitchen attention`**（后者=INT8 量化稠密注意力，
  仅 NVIDIA/AMD GPU 可用，受 `COMFY_KITCHEN_INT8_ATTENTION_IS_AVAILABLE` 门控）；
- **选项里没有 sage** ——视频「ModelAttentionBackend 加载 SageAttention」的说法与源码不符（或为更新版行为，
  0.44.0 源码为准）；SageAttention 在本生态的正路仍是 KJNodes 的
  `MiniMaxH3MemoryEfficientSageAttentionPatch`（见 `../reference.md` kijai VRAM patch 节）；
- 节点自述："When used with Block Sparse Attention, this backend is used whenever sparse attention is
  inactive or unsupported" —— 它与稀疏注意力节点是**配套设计**：稀疏不活跃/不支持时回落到这里的稠密后端。

**`BlockSparseAttention`**（display name 就是 **"Model Sparse Attention"**）——
`comfy_extras/nodes_sparse_attention.py:353-439`：

- 文件头注释：**"Block-sparse attention on comfy_kitchen's sparse attention kernels (Sol-Attn adaptive…)"**
  ——即官方核心直接把 **Sol-Attn** 自适应稀疏注意力收编为内置节点（method 选项含 `sol-attn`，
  描述为 training-free adaptive threshold per head/query block）；
- 内核走 `comfy_kitchen` 的 `sol_attn` / `sol_attn_chunked`，无编译内核时明确回落（"no compiled sol_attn
  kernel for this GPU"），并有 `start_percent` / `end_percent` / `dense_blocks` / `min_tokens` 等旋钮。

> 与 `../reference.md` Sol-Attn 章的关系：技能档案记的是**第三方包**（kijai triton 版 / KingGore flex 版）；
> 本视频点出的是**第三条路：官方核心内置** `BlockSparseAttention`（comfy-kitchen 内核）。
> 三条路同源于 arXiv 2607.24027 论文，tau/参数语义不同，照旧**不跨包抄参数**。

## KJNodes 两个显存切块节点 [t=11:30-11:54]

- 用于**显存紧张的硬件**：把模型切分成小块，**每次只计算其中一小块**，降低峰值占用，
  从而（让显存紧张机器也能）加速采样；
- 参数就是**切分块的数量**：等于 1 的时候就是不切分；
- 接线方式：**串联到模型加载的后面**（MODEL 补丁链）。

> 验证状态：**双机引擎（Mac 0.44.0 / Win）custom_nodes 均未装 KJNodes**，节点名与参数无法源码验尸，
> 按视频口径记录；已知 KJNodes 中 H3 相关件为 `MiniMaxH3MemoryEfficientSageAttentionPatch`
> （Sage 换装+省显存），与本节「切块」件疑似不同代产品，采用前先读 KJNodes 的 NODE_CLASS_MAPPINGS。

## 终态：SelfLift 二采低显存兼容版工作流 [t=11:55-12:08]

把以上模型级节点全部**串联到模型加载的后面**（UNet → LoRA → 注意力后端 → 稀疏注意力 → [切块] → 采样链），
就得到目前最全面的 **SelfLift 二采低显存兼容版工作流**——视频三套工作流的顶层形态
（基础工作流 → SelfLift 二采 → SelfLift 二采低显存兼容版，层层递进 [t=12:09-12:32]）。

## 加速手段全景表（视频体系总装）

| 层 | 手段 | 关键参数 | 代价/边界 |
|---|---|---|---|
| 采样-步数 | 4/8 步蒸馏 LoRA | strength 1.0，手动调低步数 | 质量取舍；音频头受害（我方补：出音频须 28 步纯净档） |
| 采样-分辨率分段 | 二采（前半低清） | lowres_scale 0.5、transition_step | 需 latent 放大桥接；目标≈0.5MP 以下不值得 |
| 采样-σ | H3 Sigma Refiner 补步 | extra_steps=1、cosine | 平滑过渡，非改曲线 |
| 模型-稠密注意力 | ModelAttentionBackend | pytorch / comfy kitchen (INT8) | 后者限 NVIDIA/AMD |
| 模型-稀疏注意力 | Model Sparse Attention (Sol-Attn) | method=sol-attn、start/end_percent | 无内核自动回落稠密 |
| 模型-显存切块 | KJNodes 切块（视频口径） | 块数，1=不切 | 未验尸；显存紧张硬件用 |
