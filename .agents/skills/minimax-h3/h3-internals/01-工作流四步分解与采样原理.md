# 01 · 工作流四步分解与采样原理

> 来源主题段 00:40–05:37。视频以**参考生视频（Reference-to-Video）**为主线：首尾帧生视频本质上可以用
> 参考生视频的工作流实现；正经影视创作很少用首尾帧模式，大部分靠事先生成好的资产参考图 + 提示词走参考生视频 [t=00:40-01:08]。

## 三问定纲：社区一切优化在答什么

每个 H3 工作流的改动，都在回答三件事之一 [t=00:20-00:38]：

1. **怎么减少显存占用**
2. **怎么生成得更快**
3. **怎么把画面做得更好**

看懂这三问，就能判断一个新工作流到底改了什么，也能挑选适合自己机器和创作需求的版本。

## 任意 H3 工作流 = 四步 [t=01:09-01:45]

| 步 | 干什么 | 对应节点 |
|---|---|---|
| ① 输入 | 提示词、参考素材（图片/视频/音频）、分辨率与时长设置 | 图片输入、提示词输入、分辨率设置节点 |
| ② 看懂素材 | 把素材变成模型内部能处理的内容 | CLIP（编码器）、VAE、参考节点 |
| ③ 采样 | 从一堆噪点开始，逐步生成画面和声音 | 采样节点（最耗时） |
| ④ 还原保存 | 内部结果还原成人能看的视频并落盘 | VAE 解码节点、视频保存节点 |

**「二采」的「采」就是采样的意思**：二采 = 视频生成经过两次采样；官方工作流是一次采样 [t=01:46-01:59]。

## 第②步内部：参考节点里发生了什么 [t=02:15-03:31]

数据首先进入 `MiniMaxH3ReferenceToVideo`（参考节点），内部完成两件事：

1. **CLIP 模型**把你输入的参考图片和 prompt 转化成 H3 能理解的语言，输出 **positive**（条件）。
   （本机技能档案勘正：H3 的文本+视觉编码器实际是 Qwen3-VL-32B 整模，ComfyUI 里仍走 CLIP 类型接口，
   见 `../reference.md`「Architecture」节。）
2. **Video VAE** 把输入图片压缩转换成 **Video Latent**；如有参考音频，**Audio VAE** 也压缩出 **Audio Latent**。
   两个 latent **拼接成一个大的 latent** 一并输出 [t=03:09-03:13]。

**为什么不直接处理每个像素？太大、太费显存，所以先用 VAE 压缩** [t=02:36-02:43]。
压缩过程叫**编码**，解压过程叫**解码** [t=02:44-02:50]。

**Latent 有多大，由你输入的视频分辨率和时长决定**；音频 latent 大小由时长决定 [t=02:51-03:08]。
——这句是后面一切「耗时」推导的根：分辨率↑ 或时长↑ ⇒ latent↑ ⇒ 计算量↑。

以上操作全部封装在参考节点内部，positive 和 latent 都是它的输出 [t=03:14-03:27]。

## 第③步：采样 = 降噪 [t=03:32-04:55]

- 采样的过程就是一个**降噪（Diffusion）**过程 [t=03:36-03:39]。
  「Diffusion」是学术名词；目前所有图片/视频生成式模型底层都是这个机制，包括最新的 Qwen Image 2.1 与 MOSS Image [t=03:58-04:13]。
- 以完整 20 步采样为例：最初 latent 是一堆看不出内容的噪点 → 人物轮廓出现 → 细节慢慢补齐 → 画面清晰。
  从第 1 步到第 20 步，每走一步画面就向想要的结果靠近一点；**模型分 20 轮把噪点整理成画面，
  每一轮都参考提示词和素材（positive）决定下一步怎么生成** [t=04:14-04:43]。

**耗时三因子**（设置直接影响采样时长）[t=03:39-03:56]：

- **步数**：走多少步就多少时间；
- **分辨率 / 时长**：设得越大 → latent 越大 → 计算量越大。

**步数多 = 整理机会多，效果通常更好，但更慢；现有 4 步 / 8 步加速本质都是在质量和速度之间取舍** [t=04:44-04:55]。

采样器选择器（KSamplerSelect）与调度器（BasicScheduler）不影响对工作流的整体理解 [t=04:56-05:05]。
视频概念页的示例采样链：`RandomNoise` + `BasicGuider` + `KSamplerSelect(res_multistep)` +
`BasicScheduler(simple, steps=20, denoise=1.00)` → `SamplerCustomAdvanced`。

## 第④步：解码与保存 [t=05:06-05:32]

采样前后的数据都以 latent 形式存在（为了省显存和计算量），最后由 **VAE 解压回人类能看的 sRGB 图像、
视频和音频**，拼接成一段完整视频，即 H3 生成的最终产物。

## 与本技能既有知识的接口

- 「Latent 大小 ∝ 分辨率 × 时长」与 `../SKILL.md` 的 17k+5 帧网格、~1MP 原生档是同一件事的原理侧与档位侧。
- 视频演示档 1.2MP / 16:9 / 5.0s / multiple 32（见 04 文档拓扑快照），略高于技能记载的 ~1MP 原生模板默认 1344×768。
- 双 VAE（video fp16 + audio）拼接输出与 `../reference.md`「video and audio have separate VAEs; jointly predicted」一致。
