# 节点图布局全量整治:分组互遮 / 节点出组框 / 间距过远

> 路径分类:**Architectural**(trellis-brainstorm Path Classification)——新增通用工具进 node-graph 技能、检查器加判据并修数值缺陷、全库批量手术、既有契约锚随行。按此走全量产物(prd + design + implement)。

## Goal

打开任意工作流,不用先放大再缩小来回找:分组框不互相压着、每个节点都在自己的分组框里、相邻节点离得近但不挤。一次整治把存量清掉,并立一道机器门,让这三类问题以后一出现就红,不再靠肉眼发现。

用户价值(1126 原话):「节点过于分散,放大后看不清晰全貌」「分组彼此遮盖」「分组里面的节点不能超出分组框范围」「节点彼此之间间隔太长,需要放大看,但是放大看又变得信息不完整了」「节点之间要距离近一些,但是又不能太近」。

## 术语表

| 术语 | 含义 |
|---|---|
| 作用域 | 主图,或一个子图定义(`definitions.subgraphs[]` 之一)。各有独立坐标系,布局问题按作用域分别计算 |
| GUI 工作流 | 带 `nodes`/`links`/`groups` 的画布文件(引擎侧栏可打开)。API 直投件(`-api.json` 等)没有布局,不在本役范围 |
| 可视盒 | 节点声明的 `size`,画布上实际画出来的矩形。Reroute 固定按 60×30 |
| est 盒 | 立宪检查器 `est_size` 的估算足迹,故意偏大。只用于「不新增 est 违规」 |
| 分组互遮 | 任意两个组框矩形有交集 |
| 节点出组框 | 节点可视盒与某组框相交,却没有完整落在该组框内(含「在里面但伸出去」与「在外面但探进来」) |
| 贴边 | 节点在组框内,但留白小于立宪公式(左 30 / 上 50 / 右 30 / 下 30) |
| 间距过远 | 相邻节点的可视净隙超过目标档;过近 = 可视盒真重叠,或 est 净隙低于立宪下限 |
| 整图缩放 | 在 1600×900 参考视口里看清整图所需的缩放倍数,越小越要眯眼 |
| 守门 | 整治后的立宪判据相对整治前「一项不增」的检查;容差 = 允许的增量 |
| 保序压缩 | 只收不推的整理方法:相对次序全保,过大的空隙吸到目标值,原本就小的间距不动 |
| 不动点 | 一个文件再过一遍整理器也不变(解析后深度相等)。间距的验收口径:每件都是整理器的不动点,即已是守门内能达到的最紧状态 |
| 无解件 | 某个作用域连「只修组框与出框」都过不了守门(并组后仍不过)。这类文件不写盘,单列呈报 |
| 格式特殊件 | 用标准写盘规则无法逐字节还原原格式的文件(现知 1 件)。默认不写盘、单列呈报;用户 2026-11-27 裁决该件接受整件重排格式 |
| 轻量档 | 机器门只算组框互遮与三个新判据(不算线交叉、线遮)的运行方式,全库数秒 |
| 钉死面 | 以字节、坐标、基线、蓝图、副本等方式钉住工作流文件的既有契约(见 `research/layout-pin-census-1126.md`) |
| 上游来源件 | 官方模板、社区作者件、「原件」留档;自研件 = 本项目生成或改造 |

## 需求

**R1 全量计算(只读)**:对全部 GUI 工作流逐作用域计算三类度量,产出逐件报告(件名 / 作用域 / 问题数 / 整治结果)。26 件 API 件不计。范围按用户 2026-11-27 裁决:除「范围外」列出的官方件、原件、收据钉死件外全部纳入,含社区作者件与测试夹。子图蓝图(`apps/backend/comfyui/my_nodes/subgraphs/` 下 9 件)按同一口径一并计算与整治——其中 8 件随后要按宿主同步(R8),没有宿主的 1 件直接整治。

**R2 修「分组互遮」**:整治后每个作用域任意两组框零交集。原组框的分法、标题、颜色不变。分组必须分开时允许最小必要地推开节点(这是全役唯一允许「推」的地方)。并组是最后手段:只有当两组怎么挪都分不开(分开就违反更高位的线规则)时,才把两组并成一组(标题用「A + B」),并逐件写进报告。

**R3 修「节点出组框」**:整治后每个节点要么完整落在恰好一个组框内(留白不少于立宪公式:左 30 / 上 50 / 右 30 / 下 30,机器判据 `edge_tight`),要么不与任何组框相交。原本无组的节点不被强行编组;可视盒中心落在组框内、视觉上就在组里的无组节点收编入组。组框按立宪公式重算(罩全成员并留足留白;原框比成员松的会收拢)。

**R4 修「间距过远」**:相邻节点可视净隙以目标档 `(横 H_T, 纵 V_T)`(用户裁决 2026-11-27:横 320 / 纵 180)为上限做保序压缩——只收不推;原本就小的间距不动;立宪 est 下限(横 200 / 纵 80)不破;同列对齐、行内错位等作者手排关系原样保留。它只吸空隙,不折行、不改变节点相对次序(F13:长流水线件压不动属预期,逐件如实报告)。验收口径是「每件都是整理器的不动点」。主图视图态(`extra.ds`)设为「打开即见全貌」。

**R5 不新增立宪违规(守门)**:整治后的 交叉 / 线遮 / 左向 / est 重叠 / est 过近 / 负区 相对整治前不增(容差为用户裁决 2026-11-27:每作用域交叉增量 ≤ max(3, ⌈整治前 × 10%⌉))。达不到就沿档位梯子放松,直到过守门;全不过则只做 R2、R3 不压缩;连这也过不了守门(并组后仍不过)则该件不写盘,作为「无解件」连同拦截它的数字单列呈报,由用户取舍——不替用户在「互遮」与「线规则」之间选。

**R6 只动布局**:改动只允许落在 `nodes[].pos`、`groups[].bounding`、`extra.ds`、子图边界槽 `inputs/outputs[].pos`。节点类型、数量、`size`、标题、`mode`、连线、`widgets_values`、Note 文本、`links` 表一律不动;每件改动后做「剔除布局字段 = 整治前」的结构对拍与幂等复核。写盘原样保留每件文件自己的格式(缩进、单行/多行、行尾、末尾换行),没改动的文件不碰;标准规则还原不了原格式的「格式特殊件」默认不写盘、单列呈报,经用户同意重排的件(`seethrough-layer-editor.json`,2026-11-27 裁决)按标准缩进重排写入。
